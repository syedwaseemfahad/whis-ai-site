The hiring process

Roughly four rounds: a 24-hour take-home assignment, a practical DSA-and-puzzles round, a long machine-coding/LLD round, and a system design plus managerial round with the head of engineering focused on fintech-grade concerns.

RoundFormatWhat's tested
Take-home assignment~24 hrbuild a POC (often clean-architecture, feature-rich) and share the codebase
DSA + puzzles~90 min2 practical mediums (sliding window, maps, sets, heaps) plus puzzles
Machine coding / LLD~2.5 hrclean, modular, extensible design (LRU, key-value store, game systems)
System design + managerial~90 minfintech design (idempotency, dedup, failure cases) with head of engineering

Process and cutoffs vary by drive and change over time — always confirm on the official careers page.

What to master

  • machine coding / LLD and design patterns
  • sliding window, maps, sets, heaps
  • clean architecture
  • idempotency and deduplication
  • schema design and failure cases
  • practical development tooling

Eligibility

open — SDE-1 through SDE-2+ (and interns); not CGPA-gated

Your prep plan

2-week plan

  • Days 1–4: sharpen practical DSA (sliding window, maps, sets, heaps) plus a few puzzles
  • Days 5–9: machine coding/LLD with design patterns (LRU, key-value store, game systems)
  • Days 10–12: fintech system design (idempotency, dedup, failure modes, schema at scale)
  • Day 13: timed machine coding mock plus a take-home-style build
  • Day 14: review clean architecture and tooling fluency

2-day crash plan

  • Day 1: one machine-coding build with clean patterns plus practical DSA drills
  • Day 2: one fintech system design mock (idempotency, dedup, failures)

FAQ

How is CRED different from big-tech loops?

It indexes on development skill and general tooling outside the big-tech ecosystem, machine coding, clean architecture and practical judgment matter more than LeetCode-hard puzzles.

What does the machine coding round test?

Low-level design, building clean, modular, extensible solutions like LRU caches, key-value stores or game systems, with good design patterns, error handling and passing tests.

What does the system design round emphasize?

Fintech-grade concerns: idempotency to prevent duplicate transactions, data deduplication, failure handling and schema design feasible at CRED's scale.
