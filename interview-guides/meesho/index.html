Meesho Interview Guide (2026)

Meesho's SDE process starts with a demanding DSA screen but distinguishes itself by weighting machine coding and design heavily in later rounds, reflecting the scale of its marketplace. Candidates report medium-to-hard algorithm problems early, then a hands-on build task and system-design conversations that probe real trade-offs. Clear structure, working code, and justified design choices carry the loop. Exact round counts vary by role and level, so treat ordering as typical rather than fixed.

Round-by-round: exactly what's asked & how to prepare

1

Online Assessment

~90–120 min
DSA problem-solving

A timed HackerRank-style test, often two-to-three problems weighted by difficulty, sometimes allowing your own IDE. Problems skew medium-to-hard and reward strong fundamentals in classic patterns. Passing hidden test cases and time management decide the outcome.

Example questions
  • Greedy and dynamic programming problems
  • Tree and graph traversal
  • Hashing and frequency-based problems
  • Sorting plus two-pointer or binary search
  • Careful edge-case handling under time
How to prepare
  • Grind LeetCode mediums across DP, trees, and greedy
  • Practice on HackerRank to match the platform feel
  • Time yourself on 2–3 problem sets end to end
  • Use NeetCode 150 for pattern coverage
Common mistakes
  • Chasing the hardest problem and leaving easy points unclaimed
  • Not testing against edge cases before submitting
What they look for
  • Multiple problems fully passing within the window
  • Correct pattern choice with clean complexity
2

Coding / DSA Interview

~60 min
Live algorithmic depth

A live round with 1–2 DSA problems and follow-ups on complexity and alternatives. Interviewers watch how you reason, handle edge cases, and optimize. Some candidates also get CS-fundamentals or SQL and schema questions mixed in.

Example questions
  • Optimizing brute force to optimal live
  • Graph, tree, and interval problems
  • SQL queries and schema design questions
  • OS and networking basics (DNS, OSI) as follow-ups
  • Complexity trade-off discussion
How to prepare
  • Practice narrating solutions while coding live
  • Review SQL joins and basic schema design
  • Refresh OS and networking fundamentals
  • Do mock interviews with a timer and a peer
Common mistakes
  • Silent coding with no reasoning shared
  • Ignoring interviewer hints toward the optimal path
What they look for
  • Optimal solution with clear complexity analysis
  • Comfort with adjacent CS fundamentals
3

Machine Coding / LLD

~90–120 min
Building working, extensible code

A hands-on task to implement a small working system with clean, modular, object-oriented design, sometimes run in a discussion-heavy format. They grade correctness, extensibility, and clarity of abstractions more than raw algorithm speed. You are expected to code a running solution, not pseudocode.

Example questions
  • Designing classes with clear responsibilities (SOLID)
  • Modeling an e-commerce feature (cart, orders, inventory)
  • Handling concurrency or edge conditions cleanly
  • Writing extensible, testable code under time
  • Choosing the right data structures and justifying them
How to prepare
  • Practice machine-coding katas (parking lot, cart, splitwise)
  • Learn SOLID and common design patterns
  • Rehearse building a working demo in 90 minutes
  • Read free LLD primers on common design patterns
Common mistakes
  • Over-engineering instead of delivering a working build
  • Poor class boundaries that block extensibility
What they look for
  • Clean, running, extensible code on time
  • Clear, justified abstractions and structures
4

HLD + Hiring Manager / HR

~45–60 min
System design and fit

A high-level design conversation on a scalable system plus behavioral and project discussion. Expect questions on scaling, data stores, caching, and trade-offs at marketplace scale, then motivation and team-fit questions. Communication and pragmatic choices matter most.

Example questions
  • Designing a scalable e-commerce component end to end
  • Databases, caching, and queues at scale
  • Consistency, availability, and latency trade-offs
  • Project ownership and impact stories
  • Why Meesho and how you handle fast-paced work
How to prepare
  • Study HLD basics: load balancing, caching, sharding, queues
  • Practice designing a marketplace feature aloud
  • Prepare impact-focused STAR project stories
  • Use free System Design Primer on GitHub
Common mistakes
  • Jumping to components without clarifying requirements
  • Ignoring scale and trade-offs in the design
What they look for
  • Structured design with justified trade-offs
  • Clear ownership and motivation for the role

What to master

  • Data structures and algorithms
  • Dynamic programming and greedy
  • Machine coding / low-level design
  • Object-oriented design and SOLID
  • High-level system design
  • SQL and databases
  • OS and networking basics
  • Behavioral / project impact

Eligibility

Role-based: SDE roles target strong coders across levels; campus hires need solid DSA and CS fundamentals, while lateral hires need design and delivery depth. Specifics vary by team and level.

Frequently asked questions

How much does machine coding matter?

A great deal. Meesho weights the build/LLD round heavily, so working, extensible, well-structured code is often the deciding factor.

Is the DSA bar high?

Yes, the early screens skew medium-to-hard. Strong fundamentals in DP, greedy, and graphs are important to clear them.

Do they ask system design for all levels?

HLD depth scales with level; senior roles get deeper design rounds, while juniors focus more on DSA and machine coding.
